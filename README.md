# GIFT Course Assigner
## What it is 📜
The GIFT Course Assigner is an app which assigns students to courses. Each student ranks the courses within each timeslot to indicate which courses they would most like to do. Their preferences, alongside information such as participant maximums for courses and whether the student has already been assigned another instance of that course, are used to assign students to courses. The GIFT Course Assigner by default uses Monte Carlo sampling, running many simulations in which students and courses are assigned in different orders to minimise bias from input order. From the generated samples, the best simulation is chosen for output.

## How to use 🔧
Input is given as a CSV file, which must be formatted according to the 'Source Format Example.csv' template included in this repository. There is also a configuration file 'Config.json' containing configuration options for the program. See further details below.

To start the program, run 'main.py'.

It is recommended to use a virtual environment with the necessary dependencies installed, as shown in 'requirements.txt'.

### Formatting the input CSV
When following the exemplar format shown in 'Source Format Example.csv', it is critical to match certain syntax and layout to ensure the program works. Typically, I begin with the output from Google Forms, and export to .csv from Google Sheets.

Critical elements to get right are:
* **Column Names**
  * The first column must be titled "Student Names" exactly. The column must contain the names of all the students in it's records. The last record is reserved for 'maximum participants'.
  * Column names representing courses that are instances of the same course at different times must have identical names (beware of mismatches like "D&D" with "D and D", and **_sneaky whitespaces_**). This is crucial to logic errors.
  * The underscored columns are explained below
* **Timeslots/Underscores**
  * Courses which are scheduled at the same time must be grouped, so that a student cannot be assigned to be in two places simultaneously. Underscore columns are used to demarcate group boundaries. an underscore column is *not* required after the 'Student Names' column, nor after the end of the last block.
  * Underscores should be placed in ***every row***, including column names and participant maximum rows.
  * Timeslots are typically "Saturday AM" or "Monday PM". This is not relevant to the algorithmic function but helpful to understand.
* **Participant Maximums**
  * Where the maximum is the default (16), enter 'none' (case sensitive). Participant maximums must be specified in instances where a custom value is to be used.
  * Place underscores in place of any other value in underscore columns.


### Configuration Options
The configuration file 'Config.json' must be used to set the paths for both the input and output CSV files. It also allows for the customisation of various other options:

- **_number of simulations_**: (integer). The number of simulations run for the Monte Carlo sampling. Bigger numbers will take longer and consume more memory but may improve output quality.
- **_source_file_path_**: (string). The file path to the input CSV file. In windows make sure to double up the backslashes.
- **_output_file_path_**: (string). The file path to the output CSV file. In windows make sure to double up the backslashes.
- **_allow_multiprocessing_**: (boolean). Permission to use all available CPU cores to complete task. If set to true, will complete much faster but consume significantly more system rescorses.
- **_rank_flag_threshold_**: (integer). The rank at which, when a student is assigned to a course of it's value or worse, a rank flag is generated.
- **_permit_samples_with_rank_flag_**: (boolean). If set to false, will not permit samples with rank flags to be selected.
- **_satisfaction_flag_threshold_**: (integer or float). The satisfaction score at which, when a student's score is equal to or worse than, generates a satisfaction flag.
- **_permit_samples_with_satisfaction_flag_**: (boolean). If set to false, will not permit samples with satisfaction flags to be selected.

> [!TIP]
> Remember to save 'Config.json' before beginning simulations.

## What is the satisfaction score?
A satisfaction score is a sum of all assigned courses' ranks. For example, a student who's assigned courses they ranked [1st, 3rd, 2nd, 1st] would have a satisfaction score of 7. As such, **_a lower satisfaction score value is better_**. The score provides an indicator to how satisfied an individual will be with their assignments. The average (mean) satisfaction score of all students from the output CSV file is displayed in the console after the simulations have completed. _This is a primary way to judge any adjustments made to the schedule, any decrease in the number being an improvement._

## What are flags?
Flags are generated by the program in certain situations: either when a course of a specified rank or worse is assigned or when a student's satisfaction score exceeds defined limits. These limits can be set using the configuration file (see above [Configuration Options](#configuration-options)). Flags are appended to the output CSV file and describes the flag type, who has been flagged, and in the case of a rank flag, which course and the rank of that course.
